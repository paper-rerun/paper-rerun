What had to be worked around
----------------------------
The first full pass was killed at the 64th structure and a second pass at the first one it
retried, both times by a signal from outside the process (no OOM in dmesg, 28 GB free, and
the structure it died on parses to 221 residues and 896 context atoms). Three other agents
were queueing on the same GPU lock at the time. The fix was not a code change: every pass
now only designs the ids that have no stats file yet, so a killed pass costs one structure
instead of the run. Third pass finished both models. Because of that resume, the random
draws for the last 11 LigandMPNN structures came from a fresh process with the same seed,
not from one continuous stream. The seed is recorded; nothing else about the method moved.

Also worth recording: nothing was installed or upgraded. The venv has no pandas, so the
Source Data CSV is read with the csv module.

What the installed code actually does with context atoms
--------------------------------------------------------
The claim's reading (3) says every two-letter element symbol is dropped, which would wipe
the metals out. That is wrong for this commit. data_utils.py line 648 uppercases
element_list before building element_dict, so "ZN".upper() does match. Measured: 1dwh keeps
349 of 349 non-protein non-water heavy atoms, zinc included; 1a0a keeps 691 of 691. Only
hydrogen (type 1) and genuinely unknown elements are masked. Reading (2) is what runs.

10 of the 74 biounit files carry more than one MODEL (1b01, 2zhg, 2zio, 3gna, 3lsr, 3vok,
4ato, 4e0p, 5haw, 8dwm). prody keeps the extra models as coordsets and getCoords returns
only the first, so for those 10 the symmetry copies are silently not used.
